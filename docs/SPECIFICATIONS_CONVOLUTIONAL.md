## Q3. Свёрточный код: соглашение о полиномах, сдвиге и порядке выходов

Реализуемый код: R = 1/2, K = 3, порождающие полиномы g1 = 7₈, g2 = 5₈.

**Вариант A (принятый):**

| Элемент | Соглашение |

| Полиномы | g1 = 7₈ = 111₂, g2 = 5₈ = 101₂ |

## Q4. Завершение решётки и фактическая скорость

**Вариант A (zero-tail):** в конец каждого блока из L информационных битов добавляются K − 1 = 2 нулевых бита, затем кодируется весь блок.

- передаётся `2·(L + 2)` кодовых бит;
- фактическая скорость `R_eff = L / (2·(L + 2))` — используется в расчёте σ²;
- хвостовые биты **исключаются** из подсчёта BER (сравниваются только первые L бит);
- traceback начинается из состояния 00.

**Принятое L = 10 000** → R_eff = 0.49990, штраф по энергии 0.0009 дБ.

**Принято:**
1. Zero-tail и значение L зафиксированы (код параметризован).
2. Отдельно «непрерывный» режим без хвоста **не** рассматривается: он усложняет подсчёт BER и не нужен для сравнения со схемами фиксированной длины.
3. Подтвердить, что в CSV и на графике указывается `R_eff`, а не номинальное 1/2.

## Q5. Декодер Витерби: метрика и разрешение неоднозначностей

**Вариант A:**

| Элемент | Соглашение |
|---|---|
| Решения | жёсткие |
| Метрика ветви | расстояние Хэмминга |
| Метрика пути | накопленная сумма |
| Инициализация | состояние 00 — 0, остальные — +∞ |
| ACS | add–compare–select |
| Tie-break | при равенстве метрик выбирается ветвь с **меньшим номером предыдущего состояния** |
| Конечное состояние | 00 (известно благодаря zero-tail) |
| Traceback | от состояния 00 к началу блока |
| Резервный режим | при неизвестном конечном состоянии — старт от состояния с минимальной метрикой (реализуется и тестируется, в эксперименте не используется) |
| Память | матрица решений `(L+2)×4` в `uint8`; при пакетной обработке B блоков — `(B, L+2, 4)` |

**Принято:** правило tie-break зафиксировано в реализации (влияет на воспроизводимость единичных испытаний); резервный режим в эксперименте не участвует.

## Q6. Канал, единицы энергии и нормировка

**Вариант A:**

- BPSK: 0 → +1, 1 → −1; Es = 1;
- `y = x + n`, `n ~ N(0, σ²)`;
- `σ² = 1 / (2 · R_eff · γ_b)`, где `γ_b = 10^(Eb/N0_дБ / 10)`;
- R_eff: 1 — без кодирования; 4/7 — Хэмминг; `L/(2(L+2))` — свёрточный;
- жёсткое решение: `b̂ = 1 при y < 0`, иначе 0.

**Ключевое определение:** Eb — это энергия на **информационный** бит **до** кодирования (а не на кодовый бит). Только при таком определении сравнение трёх схем корректно. Формула σ² выше уже учитывает скорость кода.

**Учёт зависимости:** ошибки на выходе декодера Хэмминга зависимы внутри блока (соседние блоки независимы при независимом шуме); это учитывается при оценке статистической неопределённости по правилу Q9.

## Q8. Статистический план: приоритет критериев

В ТЗ одновременно заданы ≥10⁶ бит на точку (жёстко) и ≥100 ошибок (по возможности); при 10 дБ они несовместимы.

**Вариант A (адаптивное накопление):**
1. `N_min = 10⁶` информационных бит на точку — всегда;
2. накопление блоками, пока `ошибок < 100` **и** `N < N_max` **и** `время < T_max`;
3. бюджет времени: **весь прогон 15–30 мин** → `T_max ≈ 30–60 с` на точку, `N_max ≈ 2·10⁶` бит (свёрточный — 10⁶);
4. причина остановки сохраняется в CSV (`target_errors` / `max_bits` / `max_time`).

**Принято:** целевое число ошибок, `N_min`, `N_max`, `T_max` зафиксированы в плане; при Eb/N0 ≥ 6 дБ статистика может быть ниже целевой — с явной пометкой.

## Q9. Точки с нулём ошибок и доверительные границы

**Вариант A:**

- BER не заменяется нулём на логарифмическом графике;
- при `e = 0` в CSV: `ber = 0`, `n_bit_errors = 0`, `ber_upper95 = 3/N`;
- на графике такая точка рисуется **стрелкой вниз** от уровня `ber_upper95`, с пометкой в легенде.

**Принято:** для точек без наблюдаемых ошибок граница считается консервативно по числу
независимых единиц (блоков/пакетов), а не по числу битов и не по правилу `3/N` для
декодированных битов. Оценка неопределённости для Хэмминга и Витерби строится по числу
**независимых блоков/пакетов**; наивный интервал по битам не применяется, так как ошибки
внутри блока зависимы и такой интервал был бы занижен.

## Q10. Какие теоретические кривые строить

**Вариант A:**

1. **Без кодирования — обязательно:** `Pb = Q(√(2·Eb/N0)) = 0.5·erfc(√(Eb/N0))`, сопоставление с экспериментом с учётом статистической погрешности.
2. **Хэмминг (7,4) —** оценка сверху по объединению для жёстких решений: `P_block = P(≥2 ошибок из 7)` при `p = Q(√(2·R·Eb/N0))`, `R = 4/7`; `P_b ≲ (2/7)·P_block`, **с явной оговоркой, что это оценка сверху, а не точная кривая**.
3. **Свёрточный код — варианты:** (a) не строить (только эксперимент); (b) верхняя граница Витерби по весовому спектру (d_free = 5); (c) асимптотическая оценка `10·lg(R·d_free/2)`.

**Принято:** (1) — да; (2) — да с оговоркой; (3) — (a): теоретическая кривая свёрточного кода не строится.

## Q11. Расчёт энергетического выигрыша

**Вариант A:**

- выигрыш — горизонтальное расстояние между кривыми при фиксированном BER: `Δ = Eb/N0_uncoded(BER) − Eb/N0_coded(BER)`;
- опорные значения BER: **10⁻², 10⁻³, 10⁻⁴** (10⁻⁵ — только при достигнутой статистике, иначе «н/д»);
- интерполяция линейная по `lg(BER)` между соседними точками;
- без экстраполяции; при недостижении — «н/д» с указанием причины.

**Принято:** набор опорных BER и правило интерполяции зафиксированы; экстраполяция не применяется.

## 4. Технические замечания (для учёта в тексте отчёта)

**Z3 (повтор).** В проекте моделируются только жёсткие решения, поэтому все выводы о выигрыше относятся только к жёсткому декодированию; формулировки выводов должны это оговаривать.

**Z2 (повтор).** BER кодированных схем при 10 дБ лежит ниже разрешающей способности эксперимента в выбранном бюджете времени. Это свойство задачи, а не дефект реализации; формулировка для отчёта зафиксирована заранее.

**Z7 (новое).** Для Хэмминга (7,4) ошибки на выходе декодера сильно зависимы внутри блока (одна ошибка канала может испортить до 4 информационных битов), поэтому наивный доверительный интервал по числу битов будет занижен. Решение — по Q9.

**Z8 (новое).** Целевые 100 ошибок при бюджете 15–30 мин достижимы только при Eb/N0 ≲ 5 дБ. Для точек 6…10 дБ указывается фактическое число ошибок и верхняя граница; такой отчёт считается корректным.
