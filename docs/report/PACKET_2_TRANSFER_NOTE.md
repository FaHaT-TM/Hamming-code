## 3. Проверка пакета

Проверка выполняется исполнением, а не декларацией:

```bash
python scripts/check_transfer_packet.py
# файлов проекта:      73
# файлов в пакете:     75 (включая 00_INDEX.md)
# побайтово сверено:   74
# объём пакета:        ≈3.4 МБ
# распределение по MIME:
#   application/json       6
#   application/pdf        6
#   image/png              6
#   text/csv               8
#   text/markdown         15
#   text/plain            33
# расхождений:         0
# ИТОГ: OK — все типы поддерживаются, копии побайтовые, состав полный
```

Что именно проверяется:

1. **тип каждого файла пакета** входит в Ваш список (по расширению → MIME);
2. **побайтовость** — SHA-256 файла пакета совпадает с SHA-256 оригинала;
3. **полнота в обе стороны** — ни один файл проекта не пропущен, в пакете нет лишних;
4. **рендер notebook** — сводка по ячейкам в `.md` совпадает с `.ipynb`
   (48 ячеек, 22 кодовых, 0 ошибок исполнения).

Машинный результат — `results/data/transfer_check.json`. Пересборка —
`python scripts/make_transfer_packet.py` (детерминированная, из `git ls-files`).

## 5. Запрос: одобрение до оформления итогового документа

**Готовое решение — оформленный итоговый документ исследования — пока НЕ создаётся.**
Причина: до этой поправки я считал, что Вы принимаете только `.md`, поэтому оформление
было приостановлено. Сейчас понятно, что поддерживаются `application/pdf`, `text/html`
и `text/markdown`, но **не** поддерживаются `.docx`, `.pptx`, `.xlsx`.

Прошу подтвердить два пункта:

1. **Достаточность пакета.** Достаточно ли `docs/packet2_pkg/` (73 файла проекта → 75 файлов
   пакета: код дословно в `text/plain`, CSV/JSON без изменений, рисунки в `image/png`,
   PDF-версии рисунков в `application/pdf`, notebook и в `application/json`, и в читаемом
   `text/markdown`) для проверки работы? Если чего-то не хватает — скажите, что именно
   и в каком из поддерживаемых типов это передать (`text/html` позволяет, например,
   отдать код с подсветкой синтаксиса одной страницей).
2. **Разрешение на оформление готового решения.** После Вашего одобрения готовый отчёт
   будет подготовлен в поддерживаемых типах:
   * `application/pdf` — итоговый документ для чтения и печати (основной формат);
   * `text/html` — та же версия с оглавлением, таблицами и встроенными рисунками
     (один самодостаточный файл, изображения внутри — `data:`-URI);
   * `text/markdown` — исходная версия текста для правок.

   Форматы `.docx`/`.pptx`/`.xlsx` создаваться не будут, так как не входят в список
   поддерживаемых. Если итоговый документ нужен именно в них, потребуется отдельная
   договорённость о том, как передавать такие файлы.

До получения ответа состав и содержание результатов не меняются, новые типы документов
не создаются.
