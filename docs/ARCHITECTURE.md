## 5. Архитектурные решения (принципы)

1. **Разделение «модель / шум / метрика».** Функции кодеков не знают о канале; канал не знает о кодах; BER считается только в `metrics.py`. Это позволяет тестировать каждый слой отдельно.
2. **Чистые функции ядра.** `hamming.encode(bits) -> bits`, `convolutional.encode(bits) -> bits`, `viterbi.decode(bits) -> bits` — без глобального состояния (кроме `rng`, который передаётся явно). Решётка строится один раз и кэшируется.
3. **Один источник истины для R.** Функция фактической скорости `R = L / (2*(L+2))` для свёрточного кода и `R = 4/7` для Хэмминга; значение сохраняется в CSV вместе с каждой точкой и используется и в `sigma²`, и в подписях графиков.
4. **BER — только по информационным битам.** Для всех схем длина сравниваемых массивов равна числу переданных информационных битов; хвостовые биты исключаются из подсчёта.
5. **Детерминированность.** Единственный источник случайности — `numpy.random.default_rng(seed)`; отдельные независимые потоки (данные / шум) создаются через `SeedSequence.spawn`, чтобы изменение объёма шума не меняло информационные биты.
6. **Данные → файл → график.** Notebook никогда не рисует по объектам в памяти, если есть сохранённый CSV; так график воспроизводим из артефактов репозитория.
7. **Быстрый и полный режимы.** `QUICK=True` (демонстрация, секунды) и полный эксперимент — раздельно; полный запускается только явным действием (§17 ТЗ).

## 7. Оценка вычислительной стоимости (предварительная)

Планка ТЗ: ≥10⁶ информационных бит на точку, 11 точек (0…10 дБ), 3 схемы, целевое ≥100 ошибок.

- **Без кодирования:** 11 · 10⁶ бит — секунды. Но при 8–10 дБ ошибок будет 4·10⁻⁴…4·10⁶⁻⁶ на 10⁶ бит, т.е. **меньше 100** → потребуется ~3·10⁷ бит на точку (≈30 с на точку, память позволяет за счёт блочной генерации).
- **Хэмминг:** векторизуется в NumPy поблочно → стоимость близка к некодированной.
- **Свёрточный код:** Витерби O(N·S) при S=4. Batch-реализация (B блоков параллельно, массивы `(B, 4)`) даёт ~10⁶ бит/несколько секунд; узкое место — обратный проход traceback (память `L·4` байт на блок).
- **Главное ограничение — не время, а достижимая статистика:** при 10 дБ BER кодированных схем ~10⁻⁸…10⁻⁹, что требует 10⁹…10¹⁰ бит. Такие точки будут помечены как «ниже разрешающей способности» с указанием верхней границы.

Итоговая политика остановки для каждой точки: `остановиться, когда (ошибок ≥ 100) ИЛИ (битов ≥ N_max) ИЛИ (время ≥ T_max)`, с обязательной фиксацией причины остановки в CSV. Финальные значения `N_max`, `T_max`, диапазон Eb/N0 зафиксированы в спецификации (Q8, Z1, Z4).

### 7.1. Бюджет времени, выбранный заказчиком (24.10.2026)

Полный эксперимент должен уложиться в **15–30 минут** суммарно (3 схемы × 11 точек). Следствия:

- `T_max` на точку ≈ 30–60 с; `N_max` снижается до ~2·10⁶ бит (свёрточный код — до 10⁶ бит);
- целевые 100 ошибок будут достигнуты только для Eb/N0 ≲ 5 дБ; для 6…10 дБ точки пойдут с фактическим числом ошибок и пометкой о точности (правило Q9) — это **явления статистики, а не ошибка реализации**;
- управляемый демонстрационный режим (`QUICK`) остаётся отдельным и занимает секунды; Notebook не запускает полный прогон автоматически.

Значения `N_max/T_max` подставляются в код из принятого плана (Q8); расширение плана не требует изменения кода (параметры вынесены в конфигурацию).
